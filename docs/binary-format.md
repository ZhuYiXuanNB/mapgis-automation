# MAPGIS 6.7 矢量文件二进制结构（实测）

> 本文所有偏移与数值均为 **实测验证**（2026-11，Windows 10 + MAPGIS 6.7）。
> 参考坐标：图 2「水系材料图」系列文件、课程设计生成的点/线文件。

## 一、三种文件的头部

| 文件 | magic (0–7) | 文件标识 (8–11) |
|---|---|---|
| `.WT` 点 | `WMAP\`D22` | 1 |
| `.WL` 线 | `WMAP\`D21` | 0 |
| `.WP` 区 | `WMAP\`D23` | 2 |

三种文件都是 **头 + 索引区 + 数据区 + 属性区** 的布局，索引区起始位置存在第 12–15 字节（int32，记为 `offset`）。

`offset` 实测值常见为 **657**（不定，必须读，不能写死）。

另：第 **264** 字节（int32）= **图元数 + 1**。

## 二、点文件 `.WT`

### 索引区（以 `offset` 为基准）

| 偏移 | 类型 | 含义 |
|---|---|---|
| `offset+0` | int32 | 坐标区起始 `coord_start` |
| `offset+4` | int32 | 坐标区大小 `coord_volumn` |
| `offset+20` | int32 | 属性区起始 `attr_start` |
| `offset+24` | int32 | 属性区大小 `attr_volumn` |

### 坐标区

每 **93 字节** 存一个点，**第一块（93 字节）为空**，所以：

```
总点数 = coord_volumn / 93 - 1
```

单点记录（相对记录起点）：

| 偏移 | 类型 | 含义 |
|---|---|---|
| +7 | double | X 坐标 |
| +15 | double | Y 坐标 |
| +37 | float | **符号高度**（图面单位 = mm） |
| +41 | float | **符号宽度** |

> X 的起点是 **+7**，不是 8 的倍数——按 4/8 对齐扫描会完全漏掉坐标，这是判断"文件里有没有点"最容易踩的坑。

实测校验：

| 文件 | 大小 | `coord_volumn` | 反算点数 | 实际点数 |
|---|---|---|---|---|
| 控制点.WT | 298 820 | 206 553 | 2 220 | 2 220 ✓ |
| 重复样.WT | 7 236 | 4 185 | 44 | 44 ✓ |

### 属性区

| 偏移 | 类型 | 含义 |
|---|---|---|
| +322 | int16 | 字段数 `fields_n` |
| +324 | int32 | 记录数 `record_n` |
| +328 | int16 | 单条记录大小 `record_volumn` |
| +349 | — | 字段定义区，每字段 39 字节 |
| `349 + 39*fields_n` | — | 记录数据，第一条为空 |

字段定义（每 39 字节）实测：名称占前 19–20 字节，其后是类型与存储位置，但**文档与实测不完全一致**（`EXT_ANGLE` / `EXT_SIZE` / `EXTSTRING` 等系统字段的实际排布需逐文件核对）。

**注记文字的存储**：文字位于属性记录内固定偏移处（实测某注记文件在记录起点 **+20**），GBK 编码、`\0` 结尾。

## 三、线文件 `.WL`

### 索引区

| 偏移 | 类型 | 含义 |
|---|---|---|
| `offset+0` | int32 | 线数据区起始 `line_start` |
| `offset+4` | int32 | 线数据区大小 `line_volumn` |
| `offset+10` | int32 | 坐标区起始 `coord_start`（**非 4 字节对齐**） |
| `offset+14` | int32 | 坐标区大小 `coord_volumn` |
| `offset+20` | int32 | 属性区起始 |
| `offset+24` | int32 | 属性区大小 |
| `offset+40` | int32 | 附加表 A 起始 |
| `offset+44` | int32 | 附加表 A 大小 |
| `offset+60` | int32 | 附加表 B 起始 |
| `offset+64` | int32 | 附加表 B 大小 |

### 线数据区

每 **57 字节** 一条线索引，第一条为空：

```
总线数 = line_volumn / 57 - 1
```

| 偏移 | 类型 | 含义 |
|---|---|---|
| +10 | int32 | 锚点数目 |
| +14 | int32 | 锚点坐标偏移（**相对坐标区起始**） |

### 坐标区

坐标区开头有 **2 字节前缀**，之后每 **16 字节** 一对双精度 X/Y。
实际取点地址 = `coord_start + 2 + 锚点偏移 + i*16`。

实测：`500m小格线.WL` = 8 397 字节，`line_volumn` 2 508 → 43 条线；`coord_volumn` 1 378 = 2 + 86×16 ✓

## 四、手工生成文件为什么一律不被识别

用上面这套结构，可以把 `.WT` / `.WL` 拼得"看得懂、读得回、点数正确"，但 **MAPGIS 一律拒绝加载**（图面为空，无报错）。

逐字节对比生成文件与可正常显示的模板，前 817 字节**只差 20 个字节**，全是被清空的三个附属段指针：

```
+20/+24   属性段      4703 / 607
+40/+44   附加表 A    6366 / 55
+60/+64   附加表 B    6813 / 1408
```

结论：

- **这三个段是必需的**，且大小按图元数量索引；
- 仅 43 条线就对应 607 字节属性 + 1408 字节附加表，内部格式无公开文档；
- 生成 1 715 条线（450 个大格号 × 3 位数字的笔画）时无法可靠推算这三段。

**实践结论：不要试图手工拼装 MAPGIS 文件。** 需要什么数据，就走软件自己的入口（投影变换、Section、输入编辑），让 MAPGIS 自己写文件；外部脚本只负责算坐标、编号、属性表。

## 五、可用的、经实测有效的外部操作

| 操作 | 可行性 |
|---|---|
| 读 `.WT` 点数 / 坐标 / 符号尺寸 | ✅ 稳定 |
| 修改已有 `.WT` 的坐标（保持其余字节原样） | ✅ 稳定（会触发一次"移除并重新添加项目"） |
| 修改已有 `.WT` 的符号尺寸（+37/+41） | ✅ 稳定 |
| 手工新建 `.WT` / `.WL` | ❌ MAPGIS 拒绝加载 |
| 手工生成注记文件（带文字） | ❌ 尾部还有按图元数索引的定位框与索引表，无法可靠扩写 |

修改已有文件后必须 **移除图层 → 重新添加项目 → 复位窗口**，否则 MAPGIS 用缓存，看不出变化。
