# 实测坑清单（MAPGIS 6.7 矢量文件读写）

> 全部来自本项目的真实调试记录；标"✅已验证"的是改完后回读/开图确认过的。

## 1. 拿 `.WL` 当 `.WT` 模板 → 输出打不开 ✅

`write_wt(..., template="图框.WL")` 会连头一起克隆，得到魔数 `WMAP\`D21` 的"点文件"，
MapGIS 直接拒绝。**模板必须同类型**：点用 `.WT`、线用 `.WL`。
自检：`assert raw[:8] == b"WMAP\`D22"`。

## 2. 属性首条空记录被当成数据 ✅

属性区 `nr = 图元数 + 1`，第 0 条是空记录。直接按下标取第 i 条 → 全部错一行，
表现为"读出来是乱码/随机数"。正确：`rows[i+1]` 对应第 i 个图元。

## 3. 字符串字段宽度不够，中文被截断 ✅

`("类型","str",12)` 装"一级水系下游"（6 汉字 = 12 字节）时，写入端按 `width-1` 留 `\0`，
结果存成"一级水系下"。**容量 ≥ 汉字数×2 + 1**，中文短标签给 16 字节最稳。

## 4. 线文件坐标区少了 2 字节前导 ✅

坐标段是 `[2B 前导][坐标对...]`，首条线的"坐标偏移"必须是 **2**。
写成 0 时所有坐标整体错位 2 字节，读出来形如 `-1.44e+203`、`-5.4e+303`——不是"坐标超范围"，是错位。

## 5. 子图号 1 在本机是怪符号，48 才是实心圆 ✅

同一符号号在不同 Slib 下含义不同。本项目机器上 `子图号=1` 显示为奇怪图形、`48` 是实心圆。
**换机器先试 48，再退到 1**；或让用户在 MapGIS 里"统一修改点参数"确认。

## 6. 标注框/标志段缺失 → 能读不能显示 ✅

点文件缺 `idx3`（框表）或 `idx4`（标志），线文件缺 `idx3/4/5/6/7`，
MapGIS 不报错但不渲染。**每段都要写**，哪怕是零块。

## 7. 头部 244/252 为 0 → 符号尺寸归零

自己造头时容易漏这两组 `f64 毫米→度系数`。为 0 时点/线/面全部不可见。克隆真实头可避免。

## 8. 中文路径与编码

字段名、字符串值都是 **GBK**；路径含中文时 `open()` 没问题，但把路径写进头里的元数据段要小心。
MAPGIS 对长中文路径支持差，工作目录建议 `C:\ws` 这类短英文路径。

## 9. CSV 往返吃掉前导零

`001A1` 用 Excel/pandas 默认读法会变 `1A1` 或 `1.0`。
读取时 `pd.read_csv(..., dtype={"点号": str})`；写 CSV 时用 `utf-8-sig`。

## 10. 生成成功 ≠ 显示正确

结构断言（点数、段长、魔数）只能保证"能被解析"。**最终一定要在 MapGIS 里开一眼**：
符号是否可见、字号是否合适、注记是否压线。换 Slib 版本后尤其如此。
