# MAPGIS 原生文件：写得出、开得开

> 字节级结构表 → [`references/format.md`](references/format.md)
> 踩坑清单 → [`references/pitfalls.md`](references/pitfalls.md)
> 要**操作 MAPGIS 桌面**（网格化、等值线、工程出图）→ 根 [`SKILL.md`](../../SKILL.md) 的界面级路线

MAPGIS 6.7 没有命令行、没有可用 COM。文件级这条路能走通，前提是搞清它**为什么静默拒收**：
图面空白、无报错、文件头校验全对 —— 十有八九是段没齐或表头计数照抄了模板。

## 0. 何时用 / 何时不用

| 用本技能 | 不用本技能 |
|---|---|
| CSV/Excel 采样点 → `.WT` 点位图 | 要 MAPGIS 做网格化、等值线、空间分析 |
| 给现成 `.WT` 加字段、改属性值、改子图号 | 要驱动菜单/对话框 |
| 由属性生成注记（点号、大格编号） | 要 MAPGIS 内部拓扑检查/构区 |
| 生成格网/图例 `.WL`、读线做分级 | 需要 `.WP` 区文件（仍未验证） |
| 校验交付文件能不能被打开 | 只是读点数、改个别坐标（直接改字节更省事） |

## 2. 三条铁律

1. **克隆骨架，不推算结构。** 从 MAPGIS 自己写出的同类文件里取：头（657 B）、16 个索引项、
   首条空记录模板、1602 B 文本池前缀、322 B 属性前缀、4 B 标志前缀、`.WL` 附加表 A/B。
   头里除魔数还有毫米→度系数、图幅框、比例尺这些"显示闸门"，造错就是"能读不能显示"。
2. **只重建"随图元数增长"的段**：坐标区、文本池、属性区、定位框（32 B/条）、标志（4+4n）。
   其余整块搬运。
3. **回填表头。** 克隆来的 260 / 264 / 304 三处一定是别人的数：
   `260 = 图元数`、`264 = 图元数+1`（都是 u16）、`304 = 4×double 显示范围`。

> 旧结论"手工拼装一律被拒"其实是**缺段**：生成件与可显示件前 817 B 只差 20 B，
> 差的是 +20/+24 属性段、+40/+44、+60/+64 三个附属段指针。段齐了就能显示（2026-11 已验收）。

## 3. 静默失败三判据（先查这个，再查数据）

| 判据 | 正常值 | 异常含义 |
|---|---|---|
| 表头 260 / 264 | 图元数 / 图元数+1 | 照抄模板 → **只画前 N 个，不报错** |
| 索引末段收尾 | == 文件长度 | 段间有空隙或截断 → 静默拒收 |
| 文本池首条偏移 | 1602（原生） | **2 = Section 方言**，本体里全白 |

`verify()` 就是把前两条自动化：`count_match` / `chain_ok` / `tail_ok` 三个都 True 才算过。

## 4. 格式速查

### 4.1 区段地图

`[657 B 头][16 × 10 B 索引][段0][段1]…`，索引项 = `<int32 起点><int32 大小><u16 0xFFFF>`，数据从 `起点+160` 开始。

| 类型 | 段0 | 段1 | 段2 | 段3 | 段4 | 段5 | 段6 | 段7 |
|---|---|---|---|---|---|---|---|---|
| `.WT` | 点记录 93 B | 文本池 | 属性 | 标注框 32 B/条 | 标志 4+4n | — | — | — |
| `.WL` | 线索引 57 B | 坐标（2 B 前导 + 16 B/顶点） | 属性 | 结点表 24 B | 附加表 A | 附加表 B | 框表 32 B/条 | 标志 4+4n |
| `.WP` | 弧索引 57 B | 坐标 + 结点表 | 元数据 | 拓扑 24 B | 55 B | 元数据 | 弧框表 | 标志 … 8 区参数 40 B、9 属性、10 区标注框、12 文件脚 |

### 4.2 `.WT` 点记录（93 B，首条为空）

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0 | u8 | 恒 1 |
| +7 / +15 | f64 | X / Y |
| +31 | u8 | 点种类：1 = 子图点，0 = 注记点 |
| +33 | i16 | 子图号（注记点：这里是 f32 字高，靠 @31 区分；>255 未实测） |
| +37 / +41 | f32 | 子图高 / 宽（注记点：字宽 / 字间隔） |
| +45 | f32 | 旋转角（度） |
| +75 | u8 | 颜色号（1 = 黑） |
| +83 | u8 | 图层号 |

### 4.3 注记记录

注记点前 7 字节换了含义：`+1 = u16 文字字节数`、`+3 = u32 文字在池内偏移`。
文本池 = **1602 B 固定样式前缀 + 逐条 GBK 首尾相接**，偏移从池首算（第一条 = 1602）。
锚点是**文字左下角**，文字向右上生长；标注框写 `(x, y-0.35h, x+可见字数×字宽×1.05, y+0.95h)`，
少了框段就是"能读不显示"。

### 4.4 `.WL` 线记录（57 B，首条为空）

`+10 = i32 顶点数`、`+14 = i32 坐标偏移（相对坐标区首）`、`+22 = i16 线型号`、`+26 = i16 颜色`、
`+30 = f32 线宽`、`+47 = u8 图层`。
**坐标区有 2 字节前导**：第一条线的偏移必须写 2，写 0 会让所有坐标整体错位，读出来是 `-1.4e+203` 之类。

### 4.5 属性表

`[322 B 前缀][u16 字段数][i32 记录数][u16 记录长][18 B][39 B × N 描述符][记录区]`

- 322 B 前缀里嵌了**表名和创建时间**，必须整块克隆，别自己造；
- 39 B 描述符 = `名称[20] | 类型 u8 | 记录内偏移 i32 | 存储宽 i16 | 声明宽 i16 | 标志 i32 | 序号 i16`；
- 类型：0 串 / 1 byte / 2 short / 3 int / 4 float / 5 double；串按 GBK，宽度含结尾 `\0`，容量 ≥ 汉字数×2+1；
- 记录数 = 图元数 + 1，首条为空；少这条空记录，属性会和点位**错开一行**。

## 5. 写点文件

```python
fields = [("点号", 0, 13, 12, 256), ("类型", 0, 17, 16, 256),
          ("X_m", 5, 8, 15, 518), ("Y_m", 5, 8, 15, 518)]   # (名, 类型, 宽, 小数位, 标志)
recs = [dict(点号="001A1", 类型="完整单元", X_m=10503.67, Y_m=57158.27)]

write_points("控制点.WT", Skeleton.from_file("参考点.WT"), recs, fields,
             symbol=48, color=134, layer=0, height=1.5, width=1.5,
             x_key="X_m", y_key="Y_m", attr_sk=None)
```

- `symbol=48` 是本机 Slib 的**实心圆**；`1` 在本机是个怪符号（见 pitfalls）；
- 坐标若来自 3 位小数 CSV，回读会有 ~1e-8 偏差 → 表现为"点数对、范围对、就是字节不一样"。要保精度就直读 `.WT`。

## 6. 写注记

```python
items = [dict(x=10510, y=57150, text=subscript("A1"), attr="001A1",
              vis=2, height=1.2, width=1.0)]
write_labels("点号.WT", Skeleton.from_file("图框.WT"), items,
             height=1.2, width=1.0, gap=0.05, color=1, layer=12,
             field="点号", attr_sk=Skeleton.from_file("控制点.WT"))
```

- `subscript()` 把 `001A1` 变成 `001A#-1`：**`#-` 后的字符排成下标**，且不占字宽；
  `A_1` / `A^1` / `A#1` 都会被原样画出，只有 `#-` 有效；
- `vis` = 可见字数（不含 `#-`），标注框按它算宽度；
- 注记骨架要取自**注记文件**（`图框.WT`），点骨架的文本池前缀不是一回事。

## 7. 写线文件

segs = [([(x0, y0), (x1, y1), (x2, y2)], (线型号, 颜色, 线宽))]

## 8. 属性：导出、就地改、由属性生成注记

| 要做什么 | 做法 |
|---|---|
| 导出属性 | `wt_attrs.py dump --wt x.WT --out attrs.csv` |
| 就地改一个值 | `wt_attrs.py set --where 点号=001C1 --set 类型=复核点` |
| 按条件批量改 | `wt_attrs.py set --where 类型=必采 --set 单元=A` |
| 只改符号/高宽/颜色 | `set_symbol.py x.WT --symbol 48 --size 2.0` |
| 属性 → 注记 | `read()` 取属性 → `write_labels()`，见配方 ③ |

就地改只重写记录区的几个字节（实测改一个字符串字段 = 7 B），文件长度、段指针、几何全不动。

## 9. 配方

**① CSV → 点位图**：`read` 不需要；直接读 CSV（`dtype=str`，别让 `001` 变 `1`）→ `write_points`。

**② 加字段 / 改值**：`wt_attrs.py set`。别为了改一个值重新生成整份文件。

**③ 属性 → 点号注记**：读点文件 → 逐点 `subscript(点号)` → `write_labels`；
   放右上角 `x+0.7, y-0.35` 是实测好看的偏移。

**④ 大格编号**：1 km 格网 → 每格中心放三位编号（`layer=13`），450 格 → 450 条注记。

**⑤ 改符号**：`set_symbol.py`，比重新生成安全（属性、注记、图层顺序都不丢）。

**⑥ 读线做分析**：`read()` 拿 `pts` → 端点吸附/打断 → 图论（Strahler 分级、汇水面积）。

## 10. 交付前必查

1. `verify()` 三个 ok：`count_match` / `chain_ok` / `tail_ok`；
2. 文本字段抽样回读，GBK 没乱码；
3. **在 MAPGIS 里真开一次**：移除旧图层 → 重新添加 → 复位窗口（按文件名缓存，不重载看不到变化）；
4. 图层号互不冲突，能分层开关。

图层号惯例：0 控制点、10 方里网、11 重复样、12 点号、13 大格号、20 图例。

## 11. 常踩的坑（完整 16 条见 references/pitfalls.md）

1. **表头计数照抄模板** → 只显示前 N 个（2220 条注记只画出 138 个就是这么来的）。
2. **322 B 属性前缀不是空的**，里面嵌表名和时间戳，必须整块克隆。
3. **`.WL` 坐标区有 2 B 前导**，偏移写成 0 就整体错位。
4. **Section 插件写的注记是另一种方言**（池从 +2、6 B/条），本体打开全白；判据看池首偏移，别试图修。
5. **改完文件必须移除图层再添加**，否则看到的是缓存。
6. **表头 260 是 u16**：单文件图元数上限 65535，超了拆层。

## 12. 文件清单与回归

| 文件 | 作用 |
|---|---|
| `scripts/mapgis_native.py` | 读写引擎：`Skeleton` / `write_points` / `write_labels` / `write_lines` / `read` / `verify` / `subscript`，另带 `verify` `inspect` `labels` 三个 CLI |
| `scripts/wt_attrs.py` | 属性导出 CSV / 按条件就地改值 |
| `scripts/set_symbol.py` | 只改子图号、高宽、颜色 |
| `scripts/selftest.py` | 回归：真实交付文件字节级比对；`--fixture` 用入库样本跑 golden 比对 |
| `tests/make_fixtures.py` | 生成最小样本（3 点 / 3 注记 / 2 线），只在有真实 MAPGIS 文件的机器上跑一次 |
| `tests/fixtures/` | 7.5 KB 入库样本，让回归在任何机器上都能跑 |
| `references/format.md` | 字节级结构表 |
| `references/pitfalls.md` | 实测坑与解法 |

```bash
python scripts/selftest.py            # 真实交付文件回归（需项目样本，缺则 SKIP）
python scripts/selftest.py --fixture   # 入库最小样本 golden 回归（任何机器可跑，3/3）
```

**两档证据，强度不同**：

| 档 | 样本 | 证明什么 | 谁能跑 |
|---|---|---|---|
| 真实回归 | 5 个真实交付文件（2220 点 / 46 重复样 / 2220 注记 / 450 格号 / 11 条图例线） | 写入器**与 MAPGIS 自己的输出字节一致** | 只有持有项目样本的机器 |
| golden 回归 | `tests/fixtures/` 的 3 点 / 3 注记 / 2 线（7.5 KB） | 写入器**没被改坏**（字节不变），不证 MAPGIS 兼容性 | 任何机器 |

golden 样本的骨架取自真实 MAPGIS 文件（`tests/make_fixtures.py` 生成一次后入库），
所以它虽然不是 MAPGIS 亲手写的，但头、文本池前缀、属性前缀、附加表都来自真实文件。

## 13. 依赖与边界

- Python 3.9+，**纯标准库**（`numpy` 只在 `grid_filter.py` 里用，与本技能无关）；
- 坐标系：文件里只有投影/椭球索引，真 CRS 依赖 `mapgis67\program\ellip.dat`；本库按"图面毫米"处理；
- `.WP` 区文件**尚未验证**：结构与线文件相近，但区参数 40 B、区标注框、文件脚这几段没有实测样本；
- 换机器或换 Slib 版本后，符号号的含义会变（本机 48 = 实心圆），重新目视确认一次。
