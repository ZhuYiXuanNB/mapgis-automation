# MAPGIS 6.7 文件层踩坑清单（合并去重）

> 每条三句：症状 → 根因 → 解法。合并自两份实测记录，按「踩到频率 / 危害」排序，不按来源分组；编号连续。
> **⚑** = 两份原始记录说法不同且无样本可裁决（2026-11-26 已用真实文件复测过一轮，能定的都定了）。方法论与自查脚本见文末附录。

## 1. 图面全白 / 「能读不显示」
**症状**：点数、坐标、文字回读全对，文件加进去什么都不画，也不报错。
**根因**：索引区不止文档写的四个指针——属性区之后还有定位框段、标志段、附加表，长度随图元数算，克隆骨架后不同步搬就指针全错；或整段缺失（点缺 idx3/idx4，线缺 idx3–7），MapGIS 同样不报错但不渲染。
**解法**：不推算、克隆骨架，只重建随图元数增长的段，每段都要写（哪怕零块），并保证「段段首尾相接、末段收尾 = 文件长度」。

## 2. 注记只画出前 N 条
**症状**：2220 条注记，图上只有左上角一小片（实测只出 138 条）。
**根因**：骨架克隆自 138 条注记的 `图框.WT`，**表头 260 / 264 的计数被一起克隆**，MapGIS 按表头渲染，多出的记录直接不画。
**解法**：写完统一回填 `pack("<H", buf, 260, n)`、`264, n+1`，并把 304 起的范围改成实际值。

## 3. 在 Section 里正常、在本体里全白
**症状**：对方给的 450 个格号文件在生成它的机器上正常，换到 MapGIS 6.7 本体打开一片空白。
**根因**：Section 用另一套组织：文本池从 **+2** 起、单条 6 字节；原生要求从 **+1602** 起（前面是样式前缀）、GBK 字节数。
**解法**：不修它，按原生骨架重制；**判据：池首偏移 2 = Section，1602 = 原生。**

## 4. 文件被直接拒绝、打不开
**症状**：`write_points(..., Skeleton.from_file("图框.WL"))` 出来的「点文件」MapGIS 直接拒绝。
**根因**：模板必须同类型——拿 `.WL` 当 `.WT` 模板会把头一起克隆，得到魔数 ``WMAP`D21`` 的点文件。
**解法**：点用 `.WT`、线用 `.WL`；自检 `assert raw[:8] == b"WMAP\`D22"`。

## 5. 坐标整体错位 2 字节（不是「坐标超范围」）
**症状**：按 93 字节整块对齐算点位全错，或线坐标读出来形如 `-1.44e+203`、`-5.4e+303`。
**根因**：坐标区前有 2 B 前导——点文件是「坐标区 + 2 B + 属性区」、注记是「坐标区 +（1602 + 文本）+ 属性区」，线文件首条线的坐标偏移必须是 **2**，写成 0 就整体错位。
**解法**：点/线都显式写这 2 B，线首条偏移固定 2；池语义点与注记不同，别混用一套偏移公式。

## 6. 点线面全部不可见（符号尺寸归零）
**症状**：结构断言全过，开图一片空，符号一个都不显示。
**根因**：自己造头时漏了 244/252 两组 `f64 毫米→度系数`，为 0 时符号尺寸归零。
**解法**：克隆真实头，或显式写入非零系数；校验清单里查 244/252 非零。

## 7. 属性数据整体错一行 / 读出来是乱码
**症状**：按下标取第 i 条属性，全部错位，值像随机数。
**根因**：属性区 `nr = 图元数 + 1`，第 0 条是空记录，直接按 `rows[i]` 取就把空记录当了数据。
**解法**：`rows[i+1]` 对应第 i 个图元；读和写都按「首条空」约定。

## 8. 属性行为异常（322 B 前缀被清零重写）
**症状**：前缀看着全是 0，清零重写后个别文件行为异常。
**根因**：前缀里嵌了**表名和创建时间**（实测 `GEOCHEM_...` 与时间戳），不是填充区。
**解法**：整块克隆自任一可用文件（点文件取点文件的前缀、注记取注记的），不要手工拼。

## 9. 字符串字段宽度不够，中文被截断
**症状**：`("类型","str",12)` 写入「一级水系下游」后读回是「一级水系下」。
**根因**：写入端按 `width-1` 留 `\0`，6 汉字 = 12 字节正好把最后一字吃掉。
**解法**：容量 ≥ 汉字数×2 + 1，中文短标签给 16 字节最稳。

## 10. 子图号显示成怪符号（Slib 相关）
**症状**：同一符号号在不同机器上形状不同：本机上 `子图号 = 1` 是奇怪图形、`48` 才是实心圆。
**根因**：符号号含义依赖 Slib 符号库，不是文件里的绝对语义。
**解法**：换机器先试 48、再退到 1，或让用户在 MapGIS 里「统一修改点参数」确认；⚑ A 侧另记 84 = 空心圈（待实测确认）。

## 11. 下标写不出来
**症状**：要印 A₁，试了 `A_1`、`A^1`、`A#1` 全被原样显示。
**根因**：原生只认 `#-` 控制符，`A#-1` 才渲染成 A₁，且 `#-` 不占字宽。
**解法**：用 **5 点探针文件**一次试 5 种写法、人眼判定——语法类未知用 5 条记录换 2220 条的确定性，成本 2 分钟。

## 12. 位置差 0.0003 mm
**症状**：注记与点坐标对不齐，偏差肉眼不可见但不为零。
**根因**：上一版从三位小数的 CSV 读坐标，精度在文本层就丢了。
**解法**：直读 `.WT` 记录里的 double——**任何需要 0 偏差的场合都不许经过格式化文本**。

## 13. 改完文件看不到变化
**症状**：替换磁盘文件后，MapGIS 里还是旧图。
**根因**：MapGIS 按**文件名**缓存已装入图层。
**解法**：**移除图层 → 添加文件 → 复位窗口**；关窗口不算。

## 14. 中文路径与编码
**症状**：中文路径在别处都正常，一旦写进头里的元数据段就出问题。
**根因**：字段名、字符串值都是 GBK；`open()` 能开中文路径，但把路径写进头里的元数据段要小心，MapGIS 对长中文路径支持差。
**解法**：字段名与字符串值一律 GBK 落盘；工作目录用 `C:\ws` 这类短英文路径。

## 15. CSV 往返吃掉前导零
**症状**：`001A1` 经 Excel/pandas 默认读法变成 `1A1` 或 `1.0`。
**根因**：默认类型推断把带前导零的编号当数值。
**解法**：读 `pd.read_csv(..., dtype={"点号": str})`；写 CSV 用 `utf-8-sig`。

## 16. 生成成功 ≠ 显示正确
**症状**：结构断言（点数、段长、魔数）全过，开图才发现符号不可见、字号不合适、注记压线。
**根因**：断言只能保证「能被解析」，不能保证渲染语义（Slib、比例、字宽、框）。
**解法**：最终一定要在 MapGIS 里开一眼；换 Slib 版本后尤其如此。

## 附 A：方法论（比任何单条都值钱）

1. **静默失败时，先 diff 模板，再调数据。** 连续三次「数据全对但文件被拒」都是拿模板逐字节 diff 才找到的。
2. **把「表头/索引与数据不同步」当成一类 bug**，而不是一个个偶发问题——它已经以四种形态出现过。
3. **文件是唯一真相**：图面不对时，先证明文件字节自洽（verify 三个 ok），再谈操作。
